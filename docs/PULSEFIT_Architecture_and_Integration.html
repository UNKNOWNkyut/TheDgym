Section 1.2 • Architectural Analysis

How the PULSEFIT Multi-Tier & Event-Driven Architecture Operates

Design Pattern: 4-Tier Async + Event-Driven
Database Governance: PostgreSQL + Composite Indexes

1. Client Presentation Tier (Decoupled SPA)

Built on React 19, TypeScript, Vite, Tailwind CSS, and GSAP (useGSAP), the client tier enforces strict role segregation via ProtectedRoute and dynamically filters navigation items by authenticated role (admin, staff, trainer, member, and unsubscribed user).

  • State Isolation: Trainers interact with the Trainer Command Center and open the ClientProgressModal to inspect active workout/meal blueprints, calculate training volume (sets × reps × weight), RPE/RIR, rest intervals, body measurements, and resting heart rate.
  • Unsubscribed Guard: Users registered under role="user" cannot unlock /dashboard/plan or /dashboard/book until verified payment promotes their session.

2. Application & Security Middleware Tier

FastAPI serves asynchronous REST routes under strict defense-in-depth middleware: HTTP-only JWT cookie extraction, database-backed JTI/session revocation (RevokedToken), fixed-window rate limiting (RateLimitHit), CSRF header validation (X-Requested-With), and automatic sensitive-secret log redaction.

  • Role Lifecycle Sweeper: Runs on server startup and every 60 seconds (main.py) plus on-request guards to auto-checkout stale visits and expire lapsed memberships (including exact 24-hour 1-Day Passes), automatically demoting expired member accounts back to user.
  • System-Wide Audit Trail: Every auth event, webhook callback, PT/class mutation, progress check-in, and member deletion writes an immutable record to audit_logs with actor role, origin IP, and user-agent.

3. High-Performance Data Tier & Pagination

PostgreSQL 16 (via SQLAlchemy 2.0 AsyncPG) persists domain entities using deterministic composite B-tree indexes such as (created_at, id) on audit_logs and users, (joined_at, id) on members, and (checked_in_at, id) on visits.

  • Zero SELECT COUNT(*) Bottlenecks: Paginated endpoints fetch limit + 1 rows ordered deterministically by ORDER BY timestamp DESC, id DESC to compute has_next in constant O(1) slice time without full-table scans.
  • In-Memory TTL Caching: ReadTTLCache caches unchanged page responses for 15 seconds without external Redis overhead and immediately invalidates matching prefixes upon writes.

4. Role Transition & Partial Index Integrity

Data consistency under concurrent hardware and payment traffic is enforced directly inside PostgreSQL rather than application locks alone:

Section 2.2 • Integration Methodology & Design Rationale

How and Why Internal Modules & External Gateways Integrate in PULSEFIT

Paradigms: API REST • Event Webhooks • Embedded ML • Hardware APIs

1. API-Based REST/JSON Integration & Contract Validation

How: All SPA-to-backend traffic flows over typed HTTP/JSON wrappers (frontend/src/services/api.ts) matched 1:1 against strict Pydantic v2 contracts (extra="forbid") in FastAPI. External biometric verification (OCR.space & Face++) and federated sign-in (Google OAuth 2.0) use non-blocking httpx.AsyncClient calls with bounded timeouts.

Why: Schema enforcement at the gateway stops malformed payloads before reaching PostgreSQL transactions, while local Tesseract/face-api fallbacks prevent cloud API outages from blocking gym floor check-ins.

2. Event-Driven Payment Webhooks & Real-Time WebSockets

How: Online plan payments integrate with Xendit via an asynchronous invoice + signed webhook pattern. Xendit pushes invoice PAID callbacks to /api/payments/webhook/xendit validated via constant-time hmac.compare_digest against XENDIT_WEBHOOK_VERIFICATION_TOKEN. In parallel, live_feed_manager broadcasts admin_notification and keycard_tap frames over WebSockets (/api/access/ws/live-feed).

Why: Webhooks guarantee eventual consistency even if the user closes the checkout browser tab before redirect return, while WebSockets deliver sub-second front-desk tap and registration alerts without polling overhead.

3. Embedded In-Process ML Churn Inference

How: Rather than hosting a separate Python/Flask prediction container, PULSEFIT serializes its trained XGBoost tree ensemble and feature scaler as auditable JSON files (churn_model.json, scaler.json). churn_pipeline.py extracts behavioral features from PostgreSQL visits, PT bookings, and revenue ledgers, computes churn probabilities directly in-process, and exposes actionable cohorts via analytics.py and retention.py (which optionally triggers SMS reminders via TextBee).

Why: Eliminating inter-service RPC reduces operational complexity, removes binary pickle deserialization security risks (Check 11), and cuts inference latency to single-digit milliseconds.

4. Hardware-Browser APIs & Closed-Loop Training Feedback

How: Reception smartphones use Chrome's NDEFReader Web NFC API (and desktop stations use HID keyboard wedge capture) to read card UIDs and hit /api/access/tap, enforcing PH end-of-day multi-day rules and exact 24-hour expiration on Day Passes. Similarly, MediaDevices drives camera capture for ID OCR & face liveness, while YourPlanPage syncs workout/meal blueprints to member_training_plans so coaches can track overload and body metrics in ClientProgressModal.

Why: Browser-native hardware integration eliminates proprietary Windows/Android driver lock-in and unites access control, biometric KYC, billing, and coaching progress into one audited PostgreSQL source of truth.
